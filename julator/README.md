# อภิธรรมชั้นจูฬโท

Interactive study site for the **จูฬโท** level of the Thai Abhidhamma curriculum —
ปริจเฉทที่ ๓ ปกิณณกสังคหะ and ปริจเฉทที่ ๗ สมุจจยสังคหะ. See [CONTEXT.md](./CONTEXT.md)
for terminology and [docs/SHARED-UNDERSTANDING.md](./docs/SHARED-UNDERSTANDING.md)
for the design.

Sibling project: `../../julatri/abhidhamma-julatri` (จูฬตรี — ปริจเฉท ๑, ๒, ๖).

## Status

**Both chapters working.** All 6 p3 นัย (`vedana`, `hetu`, `kicca`, `dvara`,
`arammana`, `vatthu`) — interactive tabs with the category rail and click/hover
cross-highlight (เวทนา adds a ๓/๕ sub-toggle). **p7 สมุจจยสังคหะ** — all 4
สังคหะ filled (๒๘ dhamma-sets, ~๑๙๘ members), bidirectional dhamma-set ↔ ๒๐๒
ปรมัตถ์ cross-reference with a 4-tab สังคหะ switcher. Nothing is committed

## Layout

```
index.html          hub  →  /julator/
p3/index.html        ปกิณณกสังคหะ tool  →  /julator/p3/
p7/index.html        สมุจจยสังคหะ tool  →  /julator/p7/
common/             style.css + ink.js (copied from julatri)
data/
  paramattha.yaml   canonical id space (จิต ๑๒๑ / เจตสิก ๕๒ / รูป ๒๘ / นิพพาน)
  p3/<scheme>.yaml  one fragment per นัย (vedana, hetu, ...); missing = stub tab
  p7/<sangaha>.yaml one hand-verified fragment per สังคหะ (akusala, missaka, ...)
  p7.yaml           generated by scripts/assemble_p7.py — do not edit
  data.json         generated — do not edit
common/shell.css   tool styles shared by p3 / p7 (rail, chips, palettes)
p3/app.js          p3 interaction (scheme-driven: rail, dots/tint, cross-highlight)
p7/app.js          p7 interaction (bidirectional set ↔ ปรมัตถ์ cross-highlight)
scripts/
  seed_paramattha.py  one-off: re-seed paramattha.yaml from julatri
  derive_p3_vedana.py  generate data/p3/vedana.yaml (verified vs reference/)
  derive_p3_hetu.py    generate data/p3/hetu.yaml   (verified vs reference/ + julatri)
  derive_p3_kicca.py   generate data/p3/kicca.yaml  (verified vs reference/ + julatri)
  derive_p3_dvara.py   generate data/p3/dvara.yaml  (verified vs reference/)
  derive_p3_arammana.py generate data/p3/arammana.yaml (verified vs reference/, internal)
  derive_p3_vatthu.py  generate data/p3/vatthu.yaml  (verified vs reference/, internal)
  assemble_p7.py      assemble data/p7/*.yaml → data/p7.yaml
  build_data.py       assemble data/p3/*.yaml + data/*.yaml → data.json
  test_p3_render.js    headless render/interaction check for p3/app.js (node)
  test_p7_render.js    headless render/interaction check for p7/app.js (node)

```

## Editing content

- Edit `data/paramattha.yaml`, `data/p3/<scheme>.yaml`, `data/p7/<sangaha>.yaml`
  — never `data/data.json` or `data/p7.yaml` (both generated).
- Verify every count and องค์ธรรม against `reference/*.md` first (see CONTEXT.md).
- Regenerate and validate:

  ```
  python3 scripts/assemble_p7.py    # data/p7/*.yaml → data/p7.yaml
  python3 scripts/build_data.py
  ```

  The build fails on any id reference that does not resolve to `paramattha.yaml`,
  and on any `expect:` count gate that does not match.
- The `data/p3/*.yaml` fragments are generated — edit the matching
  `scripts/derive_p3_*.py` and re-run it rather than hand-editing the fragment.
  The `data/p7/*.yaml` fragments are hand-verified — edit them directly, then
  re-run `scripts/assemble_p7.py`; the per-set verification record is in
  `docs/p7-verification/<sangaha>.md`.
- Commit the YAML change and the regenerated `data/data.json` together.
- After changing `p3/app.js` or the p3 data, run `node scripts/test_p3_render.js`;
  for `p7/app.js` or the p7 data, `node scripts/test_p7_render.js`.

## Running locally

Plain static site, no build step for the pages themselves:

```
python3 -m http.server 8000
```

then open `http://localhost:8000/` (hub), `/p3/`, `/p7/`.

## Deploying

GitHub Pages, project site: name the repo `julator`, deploy from the branch root.
It publishes at `<user>.github.io/julator/` with `/julator/p3/` and `/julator/p7/`
working as-is. All asset links are relative so they survive the `/julator/` base
path; add a `CNAME` file if a custom domain is set up later.
